1. Introduction                                                 *codex-intro*

codex.nvim is an unofficial, dependency-free integration for the OpenAI Codex
CLI. It requires Neovim 0.12 or newer and a `codex` executable on $PATH.

The default backend runs the complete Codex TUI in a terminal window. The
experimental app-server backend renders streamed turns, approvals, and diffs
with native Neovim UI.

2. Setup                                                        *codex-setup*

The defaults are equivalent to: >lua

  require("codex").setup({
    backend = "terminal",
    cmd = { "codex" },
    env = {},
    cwd = "root",
    root_markers = { ".git" },
    focus_after_send = false,
    terminal = {
      layout = "split",
      split_side = "right",
      split_width_percentage = 0.35,
      float = {
        width_percentage = 0.85,
        height_percentage = 0.85,
        border = "rounded",
      },
      auto_insert = true,
      auto_close = true,
      hide_keys = {},
      normal_mode_keys = {},
      window_navigation = {
        left = "<M-h>",
        down = "<M-j>",
        up = "<M-k>",
        right = "<M-l>",
      },
    },
    context = {
      max_lines = 500,
      max_bytes = 65536,
    },
    selection = {
      enabled = true,
      hint = true,
      keymaps = { ask = "<leader>aa", edit = "<leader>aE" },
    },
    app_server = {
      cmd = { "codex", "app-server" },
    },
  })
<

Set `terminal.window_navigation = false` to disable the terminal-local window
movement mappings.

Neovim terminal mode forwards `Esc` to Codex. Use <C-\><C-n> to enter
terminal Normal mode, then `v`, `V`, or `Ctrl-v` to select text and `i` or `a`
to return to terminal mode. `terminal.normal_mode_keys` installs shorter
buffer-local mappings without taking `Esc` away from Codex: >lua

  terminal = {
    normal_mode_keys = { "<M-n>" },
  }
<

Use `terminal.layout = "float"` for a centered floating TUI. Its size and
border are controlled by `terminal.float`. `terminal.hide_keys` installs
buffer-local terminal mappings that hide Codex and restore the editor. For
Ctrl-/ across terminal encodings: >lua

  terminal = {
    layout = "float",
    hide_keys = { "<C-/>", "<C-_>" },
  }
<
These keys retain their existing behavior outside the Codex terminal buffer.

Visual selections show Ask/Edit keys below the final selected line. Change
`selection.keymaps.ask` and `selection.keymaps.edit` to use other keys (or false
to disable one). Existing mappings are preserved; conflicting actions are not
advertised. Set `selection.hint = false` to hide the hint, or
`selection.enabled = false` to disable both mappings and hints.
The highlight group is CodexSelectionHint, linked to Comment by default.
With lazy.nvim, use `event = "VeryLazy"` to load before selecting text.

3. Commands                                                  *codex-commands*

                                                        *:Codex*
:Codex [args...]       Toggle the selected backend, starting Codex if needed.

                                                        *:CodexOpen*
:CodexOpen [args...]   Open and focus the selected backend.

                                                        *:CodexClose*
:CodexClose            Hide Codex without stopping its process.

                                                        *:CodexFocus*
:CodexFocus            Start, reveal, or focus Codex. Hide it when it already
                       has focus.

Prompt and context commands start the selected backend when it is not running.
Terminal input stays queued until Codex exposes its composer, so startup
screens cannot consume it. Cold starts honor `focus_after_send` while the
session starts.

                                                        *:CodexStop*
:CodexStop             Stop the managed Codex process.

                                                        *:CodexResume*
:CodexResume [--all|session]
                       Pick or resume a prior session. Without --all, the
                       picker is limited to the resolved working directory.
                       Pickers use app-server thread/list even when the
                       terminal backend is selected. A session ID goes to the
                       terminal CLI directly.

                                                        *:CodexContinue*
:CodexContinue         Resume the most recent session.

                                                        *:CodexFork*
:CodexFork [--all|session]
                       Pick or fork a prior session. The same app-server picker
                       behavior as |:CodexResume| applies.

                                                        *:CodexReview*
:CodexReview [target]  Review uncommitted changes by default. Targets include
                       --base BRANCH, --commit SHA, or custom instructions.

                                                        *:CodexImage*
:CodexImage {paths...} Start a session or turn with local image files.

                                                        *:CodexPrompt*
:CodexPrompt [text]    Send a prompt. Uses |vim.ui.input()| when omitted.

                                                        *:CodexAsk*
:[range]CodexAsk [text]
                       Compose an editable request with file or line context.
                       Without a range, include the saved file's absolute path
                       or a snapshot of a named buffer's unsaved changes.
                       Reopen an existing draft without replacing its contents.

                                                        *:CodexAskVisual*
:'<,'>CodexAskVisual [text]
                       Compose a request with the exact visual selection.

                                                        *:CodexEdit*
:'<,'>CodexEdit [text] Compose a change request with the exact visual selection.
                       Uses the selected backend, without an inline patch UI.

                                                        *:CodexFollowUp*
:CodexFollowUp [text]  Compose a multiline follow-up in the running conversation.
                       Works from the terminal or a diff without attaching its
                       buffer text. Files can be attached explicitly with Ctrl-f.
                       A stopped/replaced process or changed app-server thread
                       prevents submission and leaves the draft intact. Codex
                       TUI conversation switches remain under CLI control.

Ask/Edit open a Markdown buffer in Insert mode without starting Codex. Edit
its instructions and attached context, then use Ctrl-s or :write to submit.
Ctrl-p adds an Explain, Fix, Add tests, or Refactor instruction. Ctrl-d attaches source
diagnostics; Ctrl-f attaches a file/directory reference. Delete attachment lines
to remove them. q in Normal mode or Ctrl-c hides the draft; :CodexAsk reopens it.
Use :bdelete! in the request buffer to discard it.

                                                        *codex-input*
Input instructions appear outside the request text and are never sent to Codex:
  Insert mode:  Type your request. Ctrl-S to send. Enter for a new line.
  Normal mode:  Press i to start typing. Ctrl-S to send.
Ctrl-S Send appears above the editable text before attachment shortcuts and
stays visible when the header is shortened to fit a narrow window. The same
guidance is available for :CodexFollowUp. In Visual mode, press Esc before i.

The terminal panel has separate guidance because Enter submits there:
  Terminal input:   Type a message. Enter to send.
  Terminal Normal:  Press i to start typing.
Queued requests show a reminder to check Codex setup prompts. Once the composer
is ready, the queued request is sent automatically. Custom winbar actions are
preserved after the input instructions.
Whole-bar %! formatters keep their original winbar without the built-in hint.

The entire request is subject to the context line/byte limits. Its source cwd
is retained; sending to a different running cwd is rejected. Pending delivery
locks and hides the draft so Codex is visible, failure reopens it for retry, and
success removes it. A draft is kept only in memory, without swap or undo files.
Continue by typing in Codex or composing a :CodexFollowUp. :CodexClose returns
to editing without stopping the process; :CodexOpen brings the conversation
back. Use your Git diff integration for saved changes; :CodexDiff shows the
latest app-server turn's diff only.

                                                        *:CodexSend*
:[range]CodexSend      Send complete lines with file/range context.

                                                        *:CodexSendVisual*
:'<,'>CodexSendVisual  Send an exact character, line, or block selection.

                                                        *:CodexAddVisual*
:'<,'>CodexAddVisual   Insert an exact character, line, or block selection
                       without submitting, so the prompt can be completed in
                       Codex first.

Selections and line ranges from unnamed buffers include the text directly,
without an @path reference or a temporary file. Context receipts display
[No Name] for these buffers.

                                                        *:CodexAdd*
:CodexAdd [path]       Insert an @path reference without submitting.

                                                        *:CodexTreeAdd*
:[range]CodexTreeAdd   Insert selected paths from a supported explorer.

                                                        *:CodexSendText*
:CodexSendText[!] {text}
                       Send text. With !, insert without submitting.

                                                        *:CodexDiff*
:CodexDiff             Open the latest app-server diff.

                                                        *:CodexInterrupt*
:CodexInterrupt        Interrupt the active app-server turn.

                                                        *:CodexStatus*
:CodexStatus           Report backend, process, cwd, thread status, and the
                       last context accepted by the active session. While
                       stopped, report the cwd that the next session will use.

                                                        *:CodexHealth*
:CodexHealth           Run |:checkhealth| for codex.nvim.

4. Working directory                                            *codex-cwd*

The startup cwd is resolved from the buffer active when a session starts and
remains fixed in codex.nvim for that session. If the Codex TUI cwd is changed
with `/cd`, terminal context commands use absolute `@path` references so files
and selections still point to the intended source. |:CodexStatus| continues to
show the startup cwd.

  "root"   Nearest `root_markers` entry from the active file. Falls back to
           the file directory, then Neovim's cwd.
  "file"   Active file's directory.
  "nvim"   Neovim's current working directory.
  path     A fixed directory path.
  function(ctx)
           A callback returning a directory. ctx contains `bufnr`, `file`,
           `file_dir`, and `nvim_cwd`.

==============================================================================
5. Backends                                                *codex-backends*

TERMINAL BACKEND                                      *codex-backend-terminal*

The default and recommended backend. It runs the complete interactive Codex
TUI. Hiding its split or float preserves the terminal process. Argument-free
resume and fork pickers use app-server; provide a session ID for a CLI-only
path.

APP-SERVER BACKEND                                  *codex-backend-app-server*

Enable with `backend = "app_server"`. It starts `codex app-server` over stdio
JSONL and renders a Markdown transcript, approvals through |vim.ui.select()|,
plans, command output, and diffs. The upstream app-server API is experimental
and may change between Codex CLI releases.

6. Events                                                      *codex-events*

The following |User| autocmd patterns are emitted. Event-specific payloads are
available through `event.data`.

  CodexStarted             Terminal process started.
  CodexExited              Terminal process exited.
  CodexOpened              Hidden terminal became visible.
  CodexClosed              Terminal window was hidden.
  CodexContextSent         File, range, or selection context was sent.
  CodexPathsSent           One or more paths were sent.
  CodexAppServerReady      App-server initialization completed.
  CodexAppServerExited     App-server process exited.
  CodexThreadStarted       App-server thread started.
  CodexTurnStarted         App-server turn started.
  CodexTurnCompleted       App-server turn completed.
  CodexDiffUpdated         App-server diff changed.

Context event payloads include `kind`, `file_path`, line numbers when
applicable, `cwd`, `source`, and `submitted`. Path payloads include `paths`,
`cwd`, `source`, and `submitted`. The status receipt stores only this metadata
for the active session; selected source text is not retained in the receipt.
